# Настройка Web Push уведомлений

Web Push в проекте работает через VAPID-ключи, service worker браузера и сохраненные подписки жителей. Основная запись сообщения всегда сохраняется в личном кабинете жильца в разделе "Сообщения от УК"; браузерное уведомление является дополнительным способом показать это сообщение сразу на рабочем столе.

## Как это работает

1. Житель входит в личный кабинет.
2. Открывает раздел "Сообщения".
3. Нажимает "Разрешить уведомления в браузере".
4. Браузер запрашивает разрешение на уведомления.
5. Подписка браузера сохраняется в таблице `PushSubscriptions` и привязывается к текущему жильцу.
6. Администратор или диспетчер открывает страницу "Новое уведомление" и выбирает канал "Сообщение в профиле".
7. Сервер создает запись в таблице `Notifications`. Житель видит ее в разделе "Сообщения от УК".
8. Если у жильца есть активная браузерная подписка, сервер дополнительно отправляет Web Push.

Для локального запуска `localhost` подходит: браузеры разрешают service worker и Web Push на `localhost` без HTTPS.

## VAPID-переменные

В локальном `.env` должны быть:

```env
VAPID_PUBLIC_KEY=...
VAPID_PRIVATE_KEY=...
VAPID_SUBJECT=mailto:smartuk.uk@mail.ru
```

Публичный ключ отдается браузеру. Приватный ключ хранится только на сервере и не должен попадать в Git.

## Проверка

1. Запустить проект:

```powershell
docker compose -p smartuk up -d --build web
```

2. Открыть SmartUK: http://localhost:5000
3. В первом браузере войти как `resident101 / resident101`.
4. Открыть "Сообщения" и нажать "Разрешить уведомления в браузере".
5. Разрешить уведомления в браузере.
6. Во втором браузере войти как `admin / admin` или `dispatcher / dispatcher`.
7. Открыть "Уведомления" -> "Новое уведомление".
8. Выбрать квартиру жильца, канал "Сообщение в профиле" и отправить сообщение.

В журнале уведомлений должна появиться запись со статусом `Отправлено`. В личном кабинете жильца сообщение появится в разделе "Сообщения от УК"; при активной подписке браузер дополнительно покажет системное уведомление.
