# Настройка настоящей отправки email через Mail.ru

## 1. Создать почтовый ящик

Создайте отдельный ящик Mail.ru для курсовой, например `smartuk-demo@mail.ru`.

## 2. Создать пароль для внешнего приложения

В настройках безопасности Mail.ru создайте пароль для внешнего приложения. Для SMTP в Docker нужен именно этот пароль, а не обычный пароль от почтового ящика.

## 3. Создать локальный файл `.env`

Файл `.env` уже добавлен в `.gitignore`, поэтому реальные учетные данные не попадут в репозиторий.

Пример:

```env
SMTP_HOST=smtp.mail.ru
SMTP_PORT=2525
SMTP_USE_SSL=false
SMTP_USERNAME=smartuk-demo@mail.ru
SMTP_PASSWORD=пароль-для-внешнего-приложения
SMTP_FROM_EMAIL=smartuk-demo@mail.ru
SMTP_FROM_NAME=Диспетчер УК
```

`SMTP_USERNAME` и `SMTP_FROM_EMAIL` лучше указывать одинаковыми: Mail.ru может отклонить письмо, если отправитель не совпадает с авторизованным ящиком.

В проекте используется порт `2525` с STARTTLS: этот вариант подходит для локального Docker-стенда и был проверен на реальной доставке письма.

## 4. Обновить email тестового жителя

В демо-данных жители имеют адреса `example.local`. Для настоящего теста нужно заменить email одного жителя на реальный адрес получателя:

```powershell
docker compose -p smartuk exec -T postgres psql -U uk_user -d uk_management -c "UPDATE \"Residents\" SET \"Email\" = 'recipient@mail.ru' WHERE \"Id\" = 1;"
```

Вместо `recipient@mail.ru` укажите адрес, на который должно прийти тестовое письмо. Можно использовать тот же ящик Mail.ru.

## 5. Перезапустить веб-приложение

```powershell
docker compose -p smartuk up -d --build web
```

После этого в интерфейсе SmartUK откройте страницу "Уведомления", создайте новое уведомление для первого жителя и выберите канал `Email`.

## 6. Что делать при ошибке

Если отправка не проходит, проверьте:

- пароль именно для внешнего приложения, а не обычный пароль от ящика;
- совпадение `SMTP_USERNAME` и `SMTP_FROM_EMAIL`;
- порт `2525` и `SMTP_USE_SSL=false`;
- наличие доступа контейнера к интернету.
